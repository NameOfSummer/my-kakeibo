# 要件定義: 同期フォルダへの自動バックアップと利用明細 CSV の保存

- 状態: 未着手（2026-11-24 作成。カードの取り込み（`feat/card-csv-import`）のマージ後に実装する）
- 関係する決定: [ADR 0001](../adr/0001-browser-only-storage.md)（保存先はブラウザだけ）、[ADR 0002](../adr/0002-card-import-source-not-payment-method.md)（カードの取り込み）

## 背景

データは IndexedDB にだけあり、ブラウザのデータ消去や PC の故障で消える。今の対策は手動の JSON 書き出しだけで、取り忘れが起きやすい。また、取り込んだカードの利用明細 CSV は家計簿に残らないため、あとで元の明細を確かめられない。

Google Drive などを API で直接使う案は、OAuth（Google アカウントでの認可）が必要になり、トークンが約 1 時間で切れて承認をやり直すことになるため見送った。代わりに、PC 上で Google Drive for desktop が同期しているフォルダへブラウザから書き込み、Drive へのアップロードは同期に任せる。

## 目的

- データを変えるたびに、利用者が何もしなくてもバックアップがフォルダに残る。
- 取り込んだ利用明細 CSV の元のファイルが同じフォルダに残る。

## 範囲

### 作るもの

1. バックアップ先フォルダの設定（選ぶ・変える・やめる）
2. 自動バックアップ（変更のたびに、日ごとのファイルへ JSON を書き込む）
3. 取り込んだ利用明細 CSV の保存
4. バックアップ先の状態の表示と、再接続

### 作らないもの

- Google Drive などのクラウド API との直接の連携・OAuth
- 古いバックアップファイルの自動削除
- バックアップフォルダからの自動の復元（復元は今の「読み込み」で手動で行う）
- Safari・Firefox 向けの代わりの仕組み（今の手動の書き出しを使う）
- 端末間の同期（ADR 0001 のとおり）

## 用語

実装時に [GLOSSARY.md](../../GLOSSARY.md) に追加する。

- **バックアップ先**: 自動バックアップと CSV を書き込むフォルダ。利用者が選ぶ。Google Drive for desktop の同期フォルダを想定するが、アプリはどこのフォルダでも区別しない。
- **自動バックアップ**: データを変えるたびに、バックアップ先へ JSON を書き込むこと。手動の「書き出し」と同じ形式。

## 機能要件

### 1. バックアップ先の設定

- 「バックアップ」タブに「自動バックアップ」の欄を追加する。
- 「フォルダを選ぶ」で、ブラウザのフォルダ選択（`showDirectoryPicker`、書き込み可）を開く。
- 選んだフォルダは、次に開いたときも使う。フォルダの情報（`FileSystemDirectoryHandle`）は IndexedDB に保存する。
  - 端末ごとの設定なので、バックアップ JSON には含めない。
- 選んだ直後に、その時点のデータで 1 回バックアップする。
- 表示するもの: フォルダ名・状態（下記）・最後に保存した日時
- 操作: 「フォルダを変える」「自動バックアップをやめる」（やめるとフォルダの情報を消す。フォルダの中のファイルは消さない）

### 2. 自動バックアップ

- **いつ**: IndexedDB への保存が成功したあと。対象は取引の追加・編集・削除、取り込み、費目の追加・変更、店名ルールの追加・変更・削除、バックアップの読み込み（置き換え）。
- **何を**: 手動の書き出しと同じ JSON（`createBackup` の出力）。
- **ファイル名**: `kakeibo-backup-YYYY-MM-DD.json`（端末の時刻での日付）。同じ日のうちは上書きし、日が変われば新しいファイルにする。古いファイルは消さない。
- 書き込みは 1 つずつ順に行う。書き込み中に次の変更があれば、終わったあとに最新のデータで 1 回だけ書く（途中の状態をすべて書く必要はない）。
- 書き込みは `createWritable()` で行い、`close()` で確定する。途中で失敗しても、前のファイルの中身が壊れないようにする。
- 失敗しても IndexedDB の保存は取り消さない（保存の本体は IndexedDB のまま）。失敗は状態として表示する（下記 4）。

### 3. 利用明細 CSV の保存

- 取り込みの確認一覧で「取り込む」を押し、取引の保存が成功したら、選んだ CSV ファイルをそのままのバイト列（Shift_JIS のまま）でバックアップ先に書き込む。
- 置き場所: `<バックアップ先>/card-csv/YYYY-MM-DD_HHmmss_<元のファイル名>`
  - 日時は取り込んだ時刻。元のファイル名に使えない文字（`/ \ : * ? " < > |`）は `_` に置き換える。
  - `card-csv` フォルダがなければ作る。
- 新しく取り込む明細が 0 件で、「取り込む」を押さなかったときは保存しない。
- バックアップ先を設定していないとき、または書き込めないときも、取り込みはそのまま行う。そのうえで「CSV は保存していません（理由）」と表示する。
- CSV を保存したあとに、取引の自動バックアップも行う（2 のとおり）。

### 4. 状態の表示と再接続

状態は次の 4 つ。画面上部（今のエラー表示と同じ場所）には「再接続が必要」と「失敗」のときだけ出し、それ以外は「バックアップ」タブで表示する。

| 状態         | 条件                                                              | 表示・操作                                                                                                  |
| ------------ | ----------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------- |
| 未設定       | フォルダを選んでいない                                            | 「フォルダを選ぶ」                                                                                          |
| 有効         | 書き込みの許可がある                                              | フォルダ名と最後に保存した日時                                                                              |
| 再接続が必要 | 起動時に許可が切れていた（`queryPermission` が `granted` でない） | 「バックアップ先に再接続」ボタン。押すと `requestPermission` を呼ぶ（ボタンを押したときにしか呼べないため） |
| 失敗         | 書き込みで例外が出た（フォルダが消えた・移動したなど）            | エラーの内容と「フォルダを選び直す」                                                                        |

- 再接続が必要な間、または失敗している間の変更は IndexedDB にだけ保存する。再接続できたら、その時点のデータですぐに 1 回バックアップする。
- 非対応のブラウザ（`showDirectoryPicker` がない Safari・Firefox）では、自動バックアップの欄に「Chrome または Edge で使えます」とだけ表示し、ほかの機能には影響させない。

## 非機能要件

- npm パッケージを追加しない（標準の File System Access API だけで作る）。
- サーバー・認証・外部への通信を追加しない。
- 自動バックアップの処理で、画面の操作を待たせない（書き込みの完了を待たずに画面へ反映する）。
- テスト: フォルダ（`FileSystemDirectoryHandle`）の偽物を用意し、ファイル名・上書き・日付の切り替わり・失敗時に IndexedDB が残ること・CSV のファイル名の置き換えを確かめる。

## 実装時にやること

- ADR 0003 を書く。ADR 0001 の「アプリは自動バックアップをしない」を見直したことと、OAuth を使う案を採らなかった理由を残す。
- `DB_VERSION` を上げ、設定用のストア（バックアップ先のフォルダの情報）を追加する。バックアップ JSON の形は変えないので、`BACKUP_VERSION` はそのまま。
- README の「データとバックアップ」と GLOSSARY を更新する。

## 実装前に確かめること（未検証）

1. **Google Drive for desktop の同期フォルダを選べるか。** macOS では同期フォルダの実体が `~/Library/CloudStorage/` の下にある。Chrome はシステムに近いフォルダの選択を拒むことがあるため、選べない可能性がある（推測）。実装の最初に、実機の Chrome で `showDirectoryPicker` で選べるかを確かめる。選べない場合は、Drive for desktop の「ミラーリング」設定にするか、同期の対象に追加した別のフォルダを使う。
2. Chrome でフォルダへの書き込みの許可が、ブラウザを開き直したあとも残るか（「毎回許可」の選択肢が出るか）。残らない場合は、起動のたびに再接続のボタンを押す運用になる。
3. 書き込んだファイルが Drive に同期され、Drive の版の履歴に残るか。
